# SynRide — Relational Schema & Normalization Documentation

## 1. Relational Schema Specification

The SynRide persistent database is implemented on **Oracle AI Database 26ai Free** (`FREEPDB1`) under the schema `SYNRIDE`. The schema consists of 18 tables, 5 analytical views, 8 stored procedures, function-based unique indexes, and referential constraints.

---

## 2. Table Schemas with Keys and Constraints

### 2.1 APP_USER
Stores core user authentication credentials and account lifecycle states.
- **Columns:**
  - `user_id` NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `full_name` VARCHAR2(100) NOT NULL
  - `email` VARCHAR2(100) NOT NULL UNIQUE
  - `password_hash` VARCHAR2(255) NOT NULL
  - `user_role` VARCHAR2(20) NOT NULL CHECK (user_role IN ('STUDENT', 'FACULTY', 'ADMIN'))
  - `account_status` VARCHAR2(20) DEFAULT 'ACTIVE' NOT NULL CHECK (account_status IN ('ACTIVE', 'SUSPENDED', 'CLOSED'))
  - `created_at` TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL

### 2.2 STUDENT_PROFILE
Subtype entity capturing student-specific matriculation attributes.
- **Columns:**
  - `user_id` NUMBER(10) PRIMARY KEY, FOREIGN KEY REFERENCES `APP_USER(user_id)` ON DELETE CASCADE
  - `registration_no` VARCHAR2(20) NOT NULL UNIQUE
  - `programme` VARCHAR2(50) NOT NULL
  - `study_year` NUMBER(2) NOT NULL CHECK (study_year BETWEEN 1 AND 5)

### 2.3 FACULTY_PROFILE
Subtype entity capturing institutional teaching/non-teaching faculty attributes.
- **Columns:**
  - `user_id` NUMBER(10) PRIMARY KEY, FOREIGN KEY REFERENCES `APP_USER(user_id)` ON DELETE CASCADE
  - `employee_id` VARCHAR2(20) NOT NULL UNIQUE
  - `staff_category` VARCHAR2(20) NOT NULL CHECK (staff_category IN ('TEACHING', 'NON_TEACHING'))
  - `department` VARCHAR2(100) NOT NULL

### 2.4 USER_EMAIL_ACCOUNT
Tracks the primary institutional verified email and pending 24h change requests.
- **Columns:**
  - `email_account_id` NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `user_id` NUMBER(10) NOT NULL UNIQUE, FOREIGN KEY REFERENCES `APP_USER(user_id)`
  - `verified_email` VARCHAR2(100) NOT NULL
  - `pending_email` VARCHAR2(100)
  - `pending_email_expires_at` TIMESTAMP
  - `email_verified_at` TIMESTAMP
  - `updated_at` TIMESTAMP DEFAULT SYSTIMESTAMP

### 2.5 USER_EMAIL_VERIFICATION
One-time passcode (OTP) security registry with rate limiting and replay prevention.
- **Columns:**
  - `verification_id` NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `user_id` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `APP_USER(user_id)`
  - `email_address` VARCHAR2(100) NOT NULL
  - `verification_type` VARCHAR2(30) NOT NULL CHECK (verification_type IN ('REGISTRATION', 'EMAIL_CHANGE'))
  - `otp_hash` VARCHAR2(255) NOT NULL
  - `expires_at` TIMESTAMP NOT NULL
  - `failed_attempts` NUMBER(2) DEFAULT 0 NOT NULL
  - `status` VARCHAR2(20) DEFAULT 'PENDING' NOT NULL CHECK (status IN ('PENDING', 'VERIFIED', 'EXPIRED', 'BLOCKED'))
  - `created_at` TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL

### 2.6 EMAIL_PREFERENCE
Stores per-user communication delivery choices.
- **Columns:**
  - `preference_id` NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `user_id` NUMBER(10) NOT NULL UNIQUE, FOREIGN KEY REFERENCES `APP_USER(user_id)`
  - `email_enabled` CHAR(1) DEFAULT 'Y' NOT NULL CHECK (email_enabled IN ('Y', 'N'))
  - `updated_at` TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL

### 2.7 ROUTE_FARE
Benchmark fare pricing and travel duration reference catalog.
- **Columns:**
  - `route_id` NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `pickup_location` VARCHAR2(100) NOT NULL
  - `destination` VARCHAR2(100) NOT NULL
  - `estimated_fare` NUMBER(8,2) NOT NULL CHECK (estimated_fare >= 0)
  - `estimated_duration_minutes` NUMBER(4) DEFAULT 30 NOT NULL CHECK (estimated_duration_minutes > 0)
  - `is_active` CHAR(1) DEFAULT 'Y' NOT NULL CHECK (is_active IN ('Y', 'N'))
  - `updated_at` TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL
  - CONSTRAINT `UQ_ROUTE_POINTS` UNIQUE (`pickup_location`, `destination`)

### 2.8 RIDE_REQUEST
Intent to travel submitted by a campus user.
- **Columns:**
  - `request_id` NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `requester_id` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `APP_USER(user_id)`
  - `request_type` VARCHAR2(30) NOT NULL CHECK (request_type IN ('LOOKING_FOR_COMPANIONS', 'VEHICLE_ARRANGED'))
  - `pickup_location` VARCHAR2(100) NOT NULL
  - `destination` VARCHAR2(100) NOT NULL
  - `departure_time` TIMESTAMP NOT NULL
  - `request_status` VARCHAR2(20) DEFAULT 'ACTIVE' NOT NULL CHECK (request_status IN ('ACTIVE', 'MATCHED', 'CANCELLED', 'EXPIRED'))
  - `created_at` TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL

### 2.9 RIDE_GROUP
Collaborative ride pool container.
- **Columns:**
  - `group_id` NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `request_id` NUMBER(10), FOREIGN KEY REFERENCES `RIDE_REQUEST(request_id)`
  - `coordinator_id` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `APP_USER(user_id)`
  - `departure_time` TIMESTAMP NOT NULL
  - `group_status` VARCHAR2(20) DEFAULT 'PENDING' NOT NULL CHECK (group_status IN ('PENDING', 'CONFIRMED', 'COMPLETED', 'CANCELLED', 'EXPIRED', 'CLOSED'))
  - `estimated_fare` NUMBER(8,2) NOT NULL CHECK (estimated_fare >= 0)
  - `actual_fare` NUMBER(8,2) CHECK (actual_fare >= 0)
  - `confirmation_deadline` TIMESTAMP
  - `created_at` TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL

### 2.10 RIDE_GROUP_MEMBER
Associative entity tracking user enrollment in a ride pool.
- **Columns:**
  - `membership_id` NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `group_id` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `RIDE_GROUP(group_id)`
  - `user_id` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `APP_USER(user_id)`
  - `member_role` VARCHAR2(20) NOT NULL CHECK (member_role IN ('COORDINATOR', 'PASSENGER'))
  - `membership_status` VARCHAR2(20) DEFAULT 'PENDING' NOT NULL CHECK (membership_status IN ('PENDING', 'CONFIRMED', 'CANCELLED', 'LEFT'))
  - `joined_at` TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL
- **Function-Based Unique Index:**
  ```sql
  CREATE UNIQUE INDEX UQ_ACTIVE_GROUP_MEMBER ON RIDE_GROUP_MEMBER (
      CASE WHEN membership_status IN ('PENDING', 'CONFIRMED') THEN user_id ELSE NULL END,
      CASE WHEN membership_status IN ('PENDING', 'CONFIRMED') THEN group_id ELSE NULL END
  );
  ```
  *Design Rationale:* This allows a user to participate in subsequent attempts if they previously cancelled or left, while strictly preventing duplicate active concurrent memberships in the same group.

### 2.11 RIDE_CONFIRMATION
Explicit confirmation vote required before departure.
- **Columns:**
  - `confirmation_id` NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `membership_id` NUMBER(10) NOT NULL UNIQUE, FOREIGN KEY REFERENCES `RIDE_GROUP_MEMBER(membership_id)`
  - `confirmation_status` VARCHAR2(20) DEFAULT 'PENDING' NOT NULL CHECK (confirmation_status IN ('PENDING', 'CONFIRMED', 'DECLINED'))
  - `confirmed_at` TIMESTAMP
  - `created_at` TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL

### 2.12 FARE_SHARE
Exact mathematical split of the actual trip fare.
- **Columns:**
  - `fare_share_id` NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `group_id` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `RIDE_GROUP(group_id)`
  - `membership_id` NUMBER(10) NOT NULL UNIQUE, FOREIGN KEY REFERENCES `RIDE_GROUP_MEMBER(membership_id)`
  - `share_amount` NUMBER(8,2) NOT NULL CHECK (share_amount >= 0)
  - `payment_status` VARCHAR2(20) DEFAULT 'PENDING' NOT NULL CHECK (payment_status IN ('PENDING', 'PAID', 'FAILED', 'DISPUTED'))
  - `created_at` TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL

### 2.13 RIDE_CANCELLATION
Audit log of voluntary member departures or coordinator cancellations.
- **Columns:**
  - `cancellation_id` NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `group_id` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `RIDE_GROUP(group_id)`
  - `cancelled_by` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `APP_USER(user_id)`
  - `reason` VARCHAR2(255) NOT NULL
  - `type` VARCHAR2(30) NOT NULL CHECK (type IN ('MEMBER_WITHDRAWAL', 'COORDINATOR_CANCEL', 'AUTO_EXPIRY'))
  - `cancelled_at` TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL
  - `admin_review_required` CHAR(1) DEFAULT 'N' NOT NULL CHECK (admin_review_required IN ('Y', 'N'))
  - `review_status` VARCHAR2(20) DEFAULT 'PENDING' NOT NULL CHECK (review_status IN ('PENDING', 'REVIEWED', 'DISMISSED'))

### 2.14 RIDE_RATING
Peer evaluations submitted post-trip.
- **Columns:**
  - `rating_id` NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `group_id` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `RIDE_GROUP(group_id)`
  - `reviewer_membership_id` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `RIDE_GROUP_MEMBER(membership_id)`
  - `reviewed_membership_id` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `RIDE_GROUP_MEMBER(membership_id)`
  - `rating` NUMBER(1) NOT NULL CHECK (rating BETWEEN 1 AND 5)
  - `review_text` VARCHAR2(500)
  - `created_at` TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL
  - CONSTRAINT `UQ_PEER_RATING` UNIQUE (`group_id`, `reviewer_membership_id`, `reviewed_membership_id`)
  - CONSTRAINT `CK_NO_SELF_RATING` CHECK (`reviewer_membership_id` != `reviewed_membership_id`)

### 2.15 RIDE_REPORT
Formal complaint filing for disciplinary or completion disputes.
- **Columns:**
  - `report_id` NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `group_id` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `RIDE_GROUP(group_id)`
  - `reporter_id` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `APP_USER(user_id)`
  - `reported_user_id` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `APP_USER(user_id)`
  - `report_reason` VARCHAR2(50) NOT NULL
  - `description` VARCHAR2(1000) NOT NULL
  - `report_status` VARCHAR2(20) DEFAULT 'PENDING' NOT NULL CHECK (report_status IN ('PENDING', 'UNDER_REVIEW', 'RESOLVED', 'DISMISSED'))
  - `admin_outcome_note` VARCHAR2(1000)
  - `created_at` TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL
  - `resolved_at` TIMESTAMP

### 2.16 ADMIN_REVIEW
Administrator audit and disposition log for escalated events.
- **Columns:**
  - `review_id` NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
  - `group_id` NUMBER(10), FOREIGN KEY REFERENCES `RIDE_GROUP(group_id)`
  - `cancellation_id` NUMBER(10), FOREIGN KEY REFERENCES `RIDE_CANCELLATION(cancellation_id)`
  - `report_id` NUMBER(10), FOREIGN KEY REFERENCES `RIDE_REPORT(report_id)`
  - `assigned_admin_id` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `APP_USER(user_id)`
  - `review_reason` VARCHAR2(100) NOT NULL
  - `status` VARCHAR2(20) DEFAULT 'OPEN' NOT NULL CHECK (status IN ('OPEN', 'IN_PROGRESS', 'RESOLVED', 'DISMISSED'))
  - `outcome_note` VARCHAR2(1000)
  - `created_at` TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL
  - `reviewed_at` TIMESTAMP

### 2.17 APP_NOTIFICATION
In-application alert queue.
- **Columns:**

  - `user_id` NUMBER(10) NOT NULL, FOREIGN KEY REFERENCES `APP_USER(user_id)`

  - `last_attempt_at` TIMESTAMP
  - `next_retry_at` TIMESTAMP
  - `error_message` VARCHAR2(500)
  - `created_at` TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL

## 3. Academic SQL Views

The schema defines 5 comprehensive SQL views combining relational joins and aggregations:

1. **`V_USER_PROFILES`**: Outer-joins `APP_USER` with `STUDENT_PROFILE` and `FACULTY_PROFILE` to provide a unified profile view.
2. **`V_ACTIVE_RIDE_GROUPS`**: Joins `RIDE_GROUP`, `RIDE_REQUEST`, and coordinator user details with passenger count aggregations.
3. **`V_RIDE_GROUP_MEMBERS_DETAIL`**: Joins `RIDE_GROUP_MEMBER`, `APP_USER`, and `RIDE_CONFIRMATION` to display live confirmation statuses.
4. **`V_USER_RATINGS_SUMMARY`**: Aggregates average peer rating and review count per user from `RIDE_RATING`.
5. **`V_ADMIN_REVIEW_QUEUE`**: Unifies open reports and cancellation flags awaiting administrator disposition.

## 4. Normalization Analysis (1NF to 3NF)

### 4.1 First Normal Form (1NF)
- All attribute domains are atomic (scalar values: VARCHAR2, NUMBER, TIMESTAMP).
- No repeating groups or multivalued attributes (e.g., individual fare shares are in a separate table `FARE_SHARE` rather than an array column).
- Every table has a clearly defined primary key.

### 4.2 Second Normal Form (2NF)
- The relations are in 1NF.
- In every relation with a composite key (e.g., `RIDE_RATING` composite uniqueness `(group_id, reviewer, reviewed)`), all non-key attributes (`rating`, `review_text`, `created_at`) depend on the whole key, with no partial functional dependencies.

### 4.3 Third Normal Form (3NF)
- The relations are in 2NF.
- No transitive dependencies exist ($X \to Y$ and $Y \to Z$ where $Z$ is non-prime):
  - Example: In `RIDE_GROUP`, route coordinates are kept in `RIDE_REQUEST` or `ROUTE_FARE`; fare rates depend strictly on `ROUTE_FARE.route_id`.
  - Student registration and faculty departments reside strictly in their specialized profile relations.
